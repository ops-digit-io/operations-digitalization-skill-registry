Same three-lane flow as the new-state VSM, but every step now names the actual od-* skill that serves it and its true build state. What the correction changes. The draft VSM painted Lane 3’s branches almost entirely as gaps. Against the real registry, the connector branch 3b is Built end-to-end (mi-connector, od-signal-standardization, od-node-red-flow-builder, od-acceptance-test), and rollout (od-handover-and-adoption) is Built too. The genuine net-new work collapses to five skills — three of them the Lane 1 self-service catalog layer, which is exactly what makes retiring the standing Analytics lane safe.
Supporting spine (used across all lanes, not drawn as steps): dept-os (load-first vocabulary & honesty rules), od-portfolio-and-savings-analysis and od-scorecard-reporting (the savings/graduation loop and ODEC/COP reporting), od-sharepoint-list-export (pulling the source list).  One open decision: od-analytical-support-service is the lane-orchestrator for the Analytics lane this new state dissolves — it needs re-homing into Lane 1 self-service / Lane 2, or retiring, so the library stops encoding a service line the target model no longer has.
