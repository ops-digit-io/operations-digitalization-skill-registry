# Skill anatomy

Rules marked **spec** come from the Agent Skills specification (agentskills.io/specification, read 2026-11-10); **guide** from its best-practices guide (agentskills.io/skill-creation/best-practices, read 2026-11-10); **registry** from this registry's own checks and conventions (`scripts/validate_registry.py`, `docs/okf-conventions.md`); **proposal** is this skill's suggestion, not a rule.

## Folder

```text
skills/<name>/                     core library (a skill the process flow draws)
skills-extension/<name>/           extension library (every other skill)
  SKILL.md                         required
  references/<topic>.md            loaded on demand; one level deep from SKILL.md (spec)
  assets/<template>.md|json        templates, blanks, data files
  scripts/<tool>.py + test_<tool>.py    only if the method needs one; tested
  index.md                         generated by scripts/build_okf_index.py: never edit by hand
```

## Frontmatter of `SKILL.md`

The specification allows **six** top-level keys: `name`, `description`, `license`, `compatibility`, `metadata`, `allowed-tools` (spec). Anything else breaks packaging (registry, `docs/okf-conventions.md`), so the registry's own fields live under `metadata`:

```yaml
---
name: od-example-check              # equals the folder; 1-64 characters; lowercase, digits, hyphens (spec)
description: >-                     # 120-1024 characters in this registry (registry); what it does AND when to use it (spec)
  ...
license: MIT
metadata:
  id: od-example-check              # equals name (registry)
  tier: practice                    # foundation | lane | practice | technical (registry.yaml)
  lane: all                         # lane-1 | lane-2 | lane-3 | lane-4 | all
  owner_role: <a role, never a person>
  authority_level: <what the agent may do; must equal the registry.yaml entry>
  status: draft                     # only a human sets anything above draft; never "verified"
  sources_read: 2026-11-10
  requires: [od-context]            # every OD skill requires od-context (registry)
  derived_from:                     # free text: what was opened, with the date
    - "..."
  okf: { type: Agent Skill, title: Example check, tags: [practice], owner: human:jakob.gabriel,
         generated: { by: claude-code/1, at: 2026-11-10T00:00:00Z } }
---
```

No `⟨ ⟩` placeholder in a metadata value: a consumer would read it as the value (registry). Optional fields: `composes` (skills it hands to), `department_names` (the department's own names for it), `allowed-tools`, `compatibility`.

## Sections the registry expects in `SKILL.md`

| Section | Why | Evidence |
|---|---|---|
| `## Purpose` | One paragraph: what the skill is for and when it is worth using | SkillEvaluator discoverability check; proposal as a habit |
| `## Inputs and output` | What it needs and what it returns | SkillEvaluator reliability rule in `config/skill-quality.yaml` |
| `## Procedure` | Steps in order with a control point each; procedures rather than declarations | guide |
| `## Human gate and AI-agent notes` | What an agent may draft and what a human decides | department rule: authority levels (`od-decision-routing`) |
| `## Pitfalls` (or `## Do not`) | The failures the department has seen; the highest-value content in many skills | guide |
| `## Definition of done` (or `## Handoff`) | When the work is finished and who receives it | `config/skill-quality.yaml` |
| `## References` | A table: which file to open when | guide: say when to load each file |
| One worked example | A short, concrete input and output | guide: a working example beats exhaustive documentation |
| `## Scripts` table, if scripts ship | Script, purpose, arguments | SkillEvaluator correctness check for script-based skills |

## Size and shape

- `SKILL.md` under 500 lines and about 5,000 tokens; metadata about 100 tokens (spec, guide). Move detail into `references/`.
- References one level deep: no reference file links on to another reference (spec).
- Add what the agent would get wrong without the skill; cut what it already knows. Test: "would the agent get this wrong without this instruction?" (guide).
- Give a default, not a menu of options (guide). Match specificity to fragility: exact steps where an error is costly, freedom where it is not (guide).
- Forward slashes in paths; relative links from the skill root (spec).

## Other files

Every file other than `SKILL.md` carries ordinary OKF frontmatter: `type` (Skill Reference or Skill Asset), `title` (it must slug to the file name: `Release checklist` for `release-checklist.md`), `description`, `resource: ../SKILL.md`, `status`, `owner`, `tags`, `generated` (registry; `scripts/verify_okf.py` enforces it).

## Naming

`<family>-<object>`, lowercase kebab-case, one capability per name; a name that needs "and" is two skills (department naming convention, `OD_Skill_Naming_Convention.md`, section 1). The registry uses `od-<object>` and records the department's own name in `metadata.department_names`.

## Sources: where the content comes from

Follow the knowledge base's order: the knowledge base first, then the archive, then external sources (knowledge base rules, `AGENTS.md` Part B section 6.1). Cite only what you opened in the session; label what is internal evidence, external evidence and your own inference; never invent a figure, a name, a date or a source; refer to roles, not individuals; write in English. The registry's own tacit-knowledge practice (`PHASE1-ELICITATION.md`): resolve what you can from the department's record first, then ask the owner only the open questions, and keep what is still open visible in the skill as `to confirm` with the person who can answer.

## Where it is placed

`registry.yaml` (id, library, tier, lane, owner_role, authority_level, summary: the same words as the `SKILL.md`), `docs/new-state/process.yaml` (an extension skill is `proposed` on the step it deepens or on the spine; a core skill must be drawn on the flow and in the Mermaid file), the README table. Then regenerate: `python scripts/build_okf_index.py`, `python scripts/build_skill_map.py`, `python scripts/build_new_state_skill_map.py`.
