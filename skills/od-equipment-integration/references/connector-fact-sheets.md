# Connector fact sheets

`connectors.md` answers "is the connector available?". This file adds what
the Connector Overview records **beyond availability**: the technical limits that decide whether a
connector fits a machine, the kind of endpoint each reaches, and the build or enhancement requests
somebody wrote on the item.

**Source.** Knowledge base `Graph/Connectors` notes, quoting the `ConnectorOverview-List` SharePoint
export; machine links from `Graph/Machines`; read 2026-11-05. Texts below are paraphrases of the
Overview's own fields. **No machine counts, plant spreads or prices are carried here**: count on
the live lists, and read any written estimate on the Overview item itself.

## How to read the machine links

"Connects to N machines" on a connector note is a **graph link, made by controller family**, not
a record of what runs on the machine. Two signs: two different Siemens S7 connectors can show the
same machines, although one of them is `DO NOT USE`; and the TIA connector's linked machines match
the S7-1200 plus S7-1500 rows of the Machine List. So:

- **Record:** the machines of a family that *could* be reached by that connector.
- **Not recorded:** which connector a given machine *actually* uses. The Machine List's
  `integration_method` names the concept (edge or aggregation), not the connector. Name the
  connector in the Machine List row when you integrate (rule in [`SKILL.md`](../SKILL.md),
  Gate 4).

## Build and enhancement requests written on the items

A few connector items carry a free-text request for an enhancement or a new build, with a written
estimate. These are comments, not budgets. Treat them as a trace of who asked, not as a price:
read the amount on the Overview item, and do not quote it onward.

| Connector | What the comment asks for |
|---|---|
| `DTQ-S7-Connector` | Frequent tool changes and a tool-based PLC data model |
| `DTQ-RS232-Connector` | Bring the connector to the edge platform for plants in one region |
| `DTQ-PIOVAN-Connector` | Development for two plants |
| `DTQ-ZWICK-Connector` | Development for one plant |

⟨Whether any of these was approved or built. The Overview has no date or decision field.
Who could supply it: IIAE with the connector vendor's account owner.⟩

## What to do with this

1. When a machine is a Siemens CNC (SINUMERIK 840D SL), check the signal budget first: up to 30
   signals at 2 ms (UDP push, needs PLC program changes and G-code) versus up to 100 signals at
   about 10 ms (TCP request/response). A use case that needs more signals or faster sampling is
   outside both.
2. For camera and file endpoints (Cognex EOL camera, Keyence CSV on FTP, Optris IR, Zwick
   files, SMB shares) the route is a file or image connector, not the PLC branch. Only the
   FTP route has a connector in `Productive`.
3. Quote the exact connector name in the Machine List row and in
   `assets/guidance-protocol.md`; the machine links will not tell the next engineer which one
   was used.
4. When the Overview field you need is empty (many connector notes have no input protocol
   field, and most have no documentation), say "not recorded" and ask the IIAE; do not infer
   from the connector's name. Count on the live Overview before saying how many.
